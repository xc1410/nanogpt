# nanogpt

从零手写字符级语言模型，一步步走到 GPT（LLaMA 结构）。

数据：tiny shakespeare，1115394 个字符，65 种。前 90% 训练（1003854 个），后 10% 验证（111540 个）。`data/` 不进仓库。

## 01 统计版 bigram（`01_bigram_count.py`）

做法：数训练集里每对相邻字符出现几次，得到 65×65 的计数表；每格 +1 平滑，按行归一化成"当前字符 → 下一个字符"的概率。

| 训练 NLL | 验证 NLL | 数表耗时 |
|---|---|---|
| 2.4546 | 2.4819 | 0.28 秒（一次） |

## 02 神经网络版 bigram（`02_bigram_nn.py`）

做法：当前字符的 one-hot 乘一张 65×65 的可学习表（单层线性，无 bias），输出 logits，交叉熵；表初始全 0，SGD，lr 20，batch 1000，10 遍。

| 运行 | 训练 loss | 验证 loss | 耗时 | 样本/秒 |
|---|---|---|---|---|
| 1 | 2.4607 | 2.4900 | 113.4 秒 | 88558 |
| 2 | 2.4607 | 2.4884 | 122.5 秒 | 81945 |
| 3 | 2.4608 | 2.4919 | 124.1 秒 | 80902 |

训练前验证 loss 4.1744 = ln 65：表全 0 时 65 个字符概率相同。

## 01 和 02 对一对

- **学出来的表就是归一化的计数。** 两边是同一类模型；对 bigram 来说，直接数出的频率就是让训练 loss 最小的表。02 用梯度下降往这个解靠，10 遍后训练 loss 只比 01 高约 0.006。
- **q → u 的概率**：01 是 0.898，02 是 0.9906。训练集里 q 出现 563 次，后面全是 u，真实频率 1.0；01 的 +1 平滑把它拉到 564 / 628 = 0.898，02 没有平滑，往 1.0 走。
- **02 慢得多**：同样的结果，01 数表 0.28 秒，02 训练约 2 分钟。猜：时间主要花在 DataLoader 逐个样本取数据上，不在矩阵乘法上。
- **bigram 的极限约 2.45**：只看前一个字符，再训也下不去；要更低得让模型看更长的上下文（下一步：注意力）。
